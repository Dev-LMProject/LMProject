# 설계 검토

새 설계 또는 검토된 계약의 변경에만 읽는다. 단위 설명·적용 확인에는 해당 계약이 바뀌지 않는 한 이 절차를 반복하지 않는다.

## 역할과 지침

조정자는 요구 동작, 성공·실패·취소 경로, 영향받는 소스·호출부·설정, 미확정 결정을 정리한다. 기존 기능·임시 구현·제안을 구분하고 결정에 꼭 필요한 질문만 한다.

현재 스킬 목록에서 아래 지침의 실제 경로를 찾는다. **각 역할이 자신의 지침만 읽고**, 조정자는 경로·역할·산출물을 전달한다. 이미 같은 문맥에서 읽은 동일 버전은 재로딩하지 않는다. 설치 경로나 버전을 고정하지 않는다.

| 분리된 역할 | 읽을 지침 | 검토 범위 |
| --- | --- | --- |
| Superpowers 설계자 | `superpowers:brainstorming`, 개발 단위 구성 시 `superpowers:writing-plans` | 책임·공개 인터페이스·상태·호출 흐름·예외 경로와 검증 가능한 개발 순서 |
| Ponytail Ultra 검토자 | `ponytail:ponytail`의 Ultra 검토 지침 | 정확성·생명주기·취소·재진입·누락된 연결, 요구를 만족하는 더 작은 해법 |
| mattpocock 최종 검증자 | `mattpocock-skills:codebase-design` | 요구 충족·모듈 경계·변경 파급·개발 단위의 완결성 |

세 역할은 서로 구분된 검토 문맥에서 실행하며 모두 설계·검토만 수행한다. 각 역할은 실제 근거를 확인하고 다른 리뷰어의 결론을 승인 근거로 삼지 않는다. 실제 읽은 지침과 확인 범위를 결과에 남긴다. 필수 요구·검증·안전한 오류 처리를 단순화 명목으로 제거하지 않는다. Ultra는 이 검토 역할의 깊이이며 세션 전체의 모드를 바꾸지 않는다.

하위 스킬은 위 역할에 필요한 설계·평가 기준을 적용한다. 이 흐름의 권한·저장 위치·단위별 안내를 유지하고, 하위 스킬의 별도 작업 트리·커밋·구현 인계·중첩 검토 절차를 추가 실행하지 않는다. `brainstorming`의 Builder check는 첫 Ultra 검토에 통합한다. 설계만으로 계획할 때 잘못 추측할 질문과 이유를 찾되 위임된 세부 결정·취향은 제외한다. `writing-plans`의 자체 점검은 설계자가 하며 별도 계획 검토자를 늘리지 않는다.

지정 지침이나 독립 검토 수단이 없거나 사용자가 대체 방식을 요청하면 [대체·수동 검토](portable-review.md)를 읽는다. 가능한 조사·초안은 계속하며, 기존 선택은 다시 묻지 않는다. 플러그인을 자동 설치하거나 수행하지 않은 역할의 완료를 기록하지 않는다.

## 전달 자료와 산출물

- 첫 전달에는 요구·사용자 결정, 적용할 프로젝트 규칙과 본문의 UE 기준, 현재 설계 버전·위치, 필요한 소스·호출부·설정 위치, 검토 범위와 구현 금지를 담는다. 전체 대화를 복제하거나 모든 하위 스킬을 모든 역할에 전달하지 않는다.
- 처음 맡는 설계는 전체 계약을 읽고 관련 근거를 직접 확인한다. 공유 파일을 볼 수 있으면 경로·심벌·범위를 전달하고, 볼 수 없으면 허용된 필요한 내용을 제공한다. 비용을 이유로 필수 근거를 생략하지 않는다.
- 설계자는 계약과 개발 단위에 필요한 결정을 작성한다. 아직 요청하지 않은 모든 단위의 구현 코드·상세 설명을 미리 생성하지 않는다. 조정자만 최신 설계와 기록을 저장한다.
- 검토 결과는 `버전 / 판정 / 확인·미확인 범위`와 지적별 `ID / 중요도 / 발생 조건·근거 / 최소 수정안`으로 낸다. 문제가 없으면 짧게 판정하고 설계 전문을 되풀이하지 않는다.

## 검토 순서와 종료 조건

1. 설계자가 버전을 붙인 설계를 작성한다.
2. Ultra 검토자가 검토한다. 조치할 문제가 없으면 바로 최종 검증으로 간다.
3. 필수 지적이 있으면 설계자가 반영하거나 근거로 기각한다. 조정자가 최신 설계와 ID별 처리 근거를 갱신한다. 동작·요구·프로젝트 규칙에 영향 없는 취향은 선택 사항으로 둔다.
4. 같은 Ultra 검토자가 수정 내용과 영향을 확인한다. 해소되지 않은 필수 지적이 있으면 3으로 돌아간다.
5. mattpocock 검증자가 최신 설계 전체와 처리 근거를 독립 확인한다. 조치할 문제가 있으면 3으로 돌아가 필요한 수정·영향 확인을 거친다.

재검토는 **같은 역할을 재사용**하고 이전 확인 버전, 새 버전, 변경 부분, 지적 ID·처리 근거를 전달한다. 검토자는 변경 부분과 영향받는 계약·호출부를 확인하고 **현재 버전의 판정을 새로 낸다.** 기존 승인을 새 버전에 자동 적용하지 않는다. 수정이 경계를 넓히거나 근거가 달라졌으면 관련 검토 범위도 넓힌다. 검토자를 교체하거나 문맥을 잃었으면 최신 전체 설계와 필수 근거를 다시 읽힌다.

**완료:** 실제 Ultra와 mattpocock이 같은 최신 버전을 확인했고, 근거 있는 필수 지적이 모두 해소됐으며, mattpocock이 `남은 설계 수정 사항 없음`으로 판정했다. 정적 설계 검토는 실행 검증이나 무결함 보증이 아니다.

필요한 정보가 없거나 같은 쟁점이 새 근거 없이 반복되면 미해결 사항과 필요한 입력을 보고하고 해당 반복을 멈춘다. 횟수·토큰 한도만으로 통과시키지 않는다. 취향만 바꾸는 반복도 하지 않는다. 검토 후에는 본문의 전체 개요·단위 안내로 돌아간다.
