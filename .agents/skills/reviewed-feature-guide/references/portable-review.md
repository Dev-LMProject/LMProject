# 대체·수동 검토

지정 플러그인이나 자동 서브에이전트를 사용할 수 없거나 사용자가 대체 방식을 요청할 때 읽는다. 원본 기능 검토와 같은 권한·단계별 설명 규칙을 유지한다. 이 문서는 자체 작성한 기본 평가 기준이며 외부 플러그인의 복제본이 아니다.

## 방식 선택

원본 검토와 대체 검토 두 방식만 둔다. 자동 서브에이전트와 수동 새 대화는 검토자를 실행하는 방법이다.

| 가능한 기능과 사용자 선택 | 수행할 일 | 표시할 판정 |
| --- | --- | --- |
| 지정 스킬 사용 가능, 독립 검토자를 실행 가능 | 실제 스킬을 읽은 세 역할이 본문의 수정 반복 수행 | 원본 검토 완료 |
| 지정 스킬 일부 또는 전부 없음, 사용자가 대체 독립 검토 선택 | 아래 기본 기준으로 분리된 검토자 실행 | 대체 독립 검토 완료 |
| 자동 서브에이전트 없음, 사용자가 수동 전달 선택 | 원본 또는 대체 지침을 별도 새 대화·검토자에게 전달하고 실제 결과를 회수 | 실제 지침·독립성에 맞는 위 판정 |
| 독립 검토자를 실행할 수 없고 사용자가 독립 검토 없이 안내받기를 선택 | 한 에이전트가 역할별로 순차 점검 | 단독 점검 완료 · 독립 검토 미실행 |

대체 방식이나 독립 검토 생략을 아직 선택하지 않았다면 차이를 짧게 설명하고 한 번 확인한다. `다음 단계`만으로 독립 검토 생략을 승인한 것으로 해석하지 않는다. 직접 고른 대체 방식은 같은 과제에서 다시 묻지 않는다.

같은 대화에서 이름만 바꿔 답변하는 것은 독립 검토가 아니다. 독립 검토는 설계자와 구분된 에이전트, 별도 새 대화 또는 별도의 사람이 실제 자료를 읽고 낸 결과가 있어야 한다. 두 검토 역할도 서로 구분한다. 필요한 분리 실행 수단이 없으면 순차 수동 전달 또는 단독 점검의 한계를 적용한다.

## 대체 검토의 세 역할

1. **설계자**: 요구와 기존 코드를 연결한다. 상태 소유자, 외부에 제공할 인터페이스, 호출 순서, 성공·실패·취소 흐름, 영향을 받는 파일·설정·호출부를 정의한다. 개발 단위마다 선행 조건과 관찰 가능한 완료 기준을 둔다.
2. **정확성·단순성 검토자**: 실제 실패 조건과 누락된 연결을 찾는다. 취소·재시도·재진입·자원 수명·오류 처리·프로젝트별 제약을 필요한 범위에서 확인한다. 요구를 모두 만족하는 더 작은 해법을 제안하고, 근거 없는 확장이나 추상화는 줄인다. 설계만 보고 계획할 때 잘못 추측하게 되는 질문과 이유를 지적하되, 구현자에게 맡긴 세부 결정과 취향은 제외한다.
3. **최종 설계 검증자**: 최신 설계 전체를 요구·자료와 독립적으로 대조한다. 사용자가 알아야 하는 인터페이스가 불필요하게 복잡하지 않은지, 상태와 변경 책임이 한곳에 모이는지, 호출부에 내부 사정을 떠넘기지 않는지 확인한다. 각 설명 단위가 정확한 위치·연결·검증 방법을 갖추는지 판정한다.

설계자 → 정확성·단순성 검토자 → 설계 수정 → 같은 버전 재검토 → 최종 설계 검증자 순서로 수행한다. 마지막 검증에서 조치할 문제가 나오면 설계자에게 되돌려 같은 순서로 반복한다. 지적은 `ID / 중요도 / 조건과 근거 / 최소 수정안`으로 기록하고, 반영 또는 기각 근거를 남긴다.

대체 독립 검토는 **사용자가 그 방식을 선택했고**, 분리된 두 검토자가 동일한 최신 버전을 확인하고 필수 수정 사항이 해소됐을 때만 완료다. 결과를 `Ponytail Ultra 검토 완료`나 `mattpocock 검증 완료`로 부르지 않는다. 실제 사용한 지침과 검토 방법을 기록한다.

단독 점검은 독립 검토 완료 조건을 충족하지 않는다. 사용자가 독립 검토 없이 안내받기를 명시적으로 선택한 경우에만 한계를 표시한 채 단계 설명을 준비한다. 이후에도 한 단위 설명은 별도의 사용자 요청에 따른다. 구현 권한은 따로 필요하다.

## 자동 서브에이전트가 없을 때 인계

사용자가 수동 전달을 선택하면 아래 자료를 복사 가능한 블록으로 제공한다. 호스트가 지원하는 새 대화 또는 별도 검토자에게 전달하도록 안내하고 결과를 기다린다. 다른 사람에게 메시지를 대신 보내거나 다른 계정에 자동 게시하지 않는다.

```text
검토 방식: 원본 또는 대체
담당 역할:
역할 지침: 실제 사용할 스킬 문서 또는 이 문서의 해당 평가 기준
요구사항과 이미 확정된 사용자 결정:
설계 버전과 설계 전문:
자료 범위: 직접 확인한 파일/스냅샷/사용자 제공 자료의 구분
검토에 필요한 소스·호출부·설정 내용:
이전 지적과 처리 근거:
이번 검토 범위와 남은 질문:
권한: 설계·검토만. 구현, 파일 수정, 외부 전송은 하지 않는다.
출력: 확인한 설계 버전, 실제 읽은 자료와 지침, 지적별 근거·최소 수정안, 미확인 범위, 판정
```

새 대화가 원래 대화나 로컬 경로를 볼 수 있다고 가정하지 않는다. 열 수 없는 경로만 전달하지 말고 허용된 범위의 관련 내용을 함께 제공한다. 새 대화에서의 스킬 사용도 실제로 읽을 수 있는 문서가 있어야 한다. 개인정보·비밀값·무관한 프로젝트 자료는 인계하지 않는다.

회수한 결과의 버전과 자료 범위를 대조한다. 구버전 판정, 누락된 자료, 실제로 읽지 않은 지침에 대한 승인은 완료 근거에서 제외한다. 검토의 독립성과 자료가 충분하지 않으면 보완을 요청하고 확인하지 못한 사실을 채워 넣지 않는다.
