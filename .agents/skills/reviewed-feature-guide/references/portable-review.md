# 대체·수동 검토

지정 지침·자동 서브에이전트를 쓸 수 없거나 사용자가 대체 방식을 요청할 때만 읽는다. 권한·기록·전달 범위·변경분 재검토는 [설계 검토](design-review.md)의 공통 절차를 따른다. 아래 기준은 자체 작성한 대체 기준이며 외부 플러그인의 복제본이 아니다.

## 방식 선택

| 사용 가능한 수단과 사용자 선택 | 수행·표시 |
| --- | --- |
| 지정 스킬과 독립 검토자 사용 가능 | 실제 지침을 읽은 세 역할로 검토 → 원본 검토 완료 |
| 지정 스킬 누락, 대체 독립 검토 선택 | 아래 세 역할로 검토 → 대체 독립 검토 완료 |
| 자동 서브에이전트 없음, 수동 전달 선택 | 원본 또는 대체 지침을 별도 새 대화·검토자에게 전달하고 실제 결과 회수 → 실제 지침·독립성에 맞는 판정 |
| 독립 검토 불가, 단독 안내 선택 | 한 에이전트가 순차 점검 → 단독 점검 완료 · 독립 검토 미실행 |

대체 방식이나 독립 검토 생략을 선택하지 않았다면 차이를 설명하고 한 번 확인한다. 기존 선택은 유지하며 `다음 단계`만으로 독립 검토 생략을 승인한 것으로 해석하지 않는다.

독립 검토는 설계자 및 두 검토자가 서로 구분된 에이전트·새 대화·사람으로서 실제 자료를 확인해야 한다. 같은 대화에서 역할 이름만 바꾸는 것은 독립 검토가 아니다.

## 대체 역할과 완료 조건

- **설계자:** 요구·소스에 근거한 상태 소유자·공개 인터페이스·호출 순서·성공/실패/취소 흐름, 영향받는 파일·설정·호출부, 선행 조건과 관찰 가능한 단위별 완료 기준.
- **정확성·단순성 검토자:** 실패 조건·누락된 연결·취소/재시도/재진입·자원 수명·오류 처리·프로젝트 제약. 요구를 모두 만족하는 최소 해법과 계획을 막는 미확정 질문. 필수 검증과 오류 처리를 단순화 명목으로 제거하지 않는다.
- **최종 설계 검증자:** 최신 전체 설계를 요구·근거와 대조. 모듈 경계·상태 및 변경 책임·호출부 부담, 단위별 위치·연결·검증 방법의 완결성.

설계자 → 정확성·단순성 검토자 → 필요한 수정·재확인 → 최종 설계 검증자 순서로 진행한다. 마지막 지적도 설계 수정과 영향 확인을 거친다.

**대체 독립 검토 완료:** 사용자가 이 방식을 선택했고 두 독립 검토자가 같은 최신 버전을 확인했으며 필수 지적이 모두 해소됨. 실제 사용한 지침과 방식을 기록하고 `Ponytail Ultra`·`mattpocock` 검토 완료로 표시하지 않는다.

단독 점검은 사용자가 명시적으로 선택한 경우에만 한계를 표시하고 안내한다. 독립 검토 완료와 구분하며, 전체 개요 이후 단위 설명·구현은 각각 기존 권한 규칙을 따른다.

## 수동 인계

수동 전달을 선택하면 다음 자료를 복사 가능한 블록으로 제공하고 실제 결과를 기다린다. 메시지 전송이나 외부 게시를 대신 수행하지 않는다.

```text
검토 방식·담당 역할·실제로 읽을 지침:
요구·사용자 결정·프로젝트 제약:
자료 접근 범위와 현재 설계 버전:
최초/검토자 교체: 최신 전체 설계와 필수 근거
같은 검토자 재검토: 이전 버전, 변경 부분, 영향 범위, 지적 ID·처리 근거
이번 확인 범위와 남은 질문:
권한: 설계·검토만. 구현·파일 수정·외부 전송 금지.
출력: 버전·실제 읽은 자료와 지침·지적과 최소 수정안·미확인 범위·판정
```

상대가 원래 대화나 로컬 경로를 볼 수 있다고 가정하지 않는다. 열 수 없는 경로 대신 허용된 필요한 내용을 제공하고 비밀값·무관한 자료는 제외한다. 회수한 결과의 버전·실제 자료·독립성을 확인하며 부족하면 보완을 요청한다. 구버전 판정이나 읽지 않은 지침의 승인은 완료 근거로 쓰지 않는다.
