# 16진수 해킹 컴포넌트 설계 v3

기준: shd/dev_HackingSystem @ b06177d, 단일 로컬 플레이어, 단말 액터가 살아 있는 동안. 소스/BP 변경 전 설계. 근거 링크와 브랜치 이력은 [findings.md](findings.md).

## 플레이 계약
선택한 잠긴 단말에 E → 16진수 퍼즐 → 성공 메시지·작성된 ResultText → 사용자가 닫기/ESC → **단말 자체는 해금만** → **다음 E에서 현재 조건을 다시 검사하고 본래 Interact**. 이 결정은 사용자 확인 및 두 업무 카드의 11/5 결정이다. 다른 문·기믹에 대한 지정 보상은 확인 시 1회다. 일반 대상과 처음부터 완료된 단말은 퍼즐/보상 없이 본래 Interact로 간다. 실패·취소·시작 거절에 본래 기능으로 빠지는 경로가 없어야 한다.

## 어디에 이어 붙일지
- ULMInteractorComponent::TryInteract가 등록 대상인지 확인한다. ULMInteractionComponent::RequestInteraction은 대상/요청자/인터페이스, 합산 Busy(아래 2번), 기존 상호작용 종류의 HasAny 호환성을 판정하고, 잠긴 대상만 TryStartHacking으로 보낸다. 기존 true/Succsess는 '요청이 수락됨'이다. 완료 때 여기로 재귀 호출하지 않는다. E/Execute_Interact를 BP에도 이중 연결하지 않는다.
- 종류와 잠금 상태는 다른 축이다. 단말의 종류는 LM.Interaction.Actor.Hacking이고, 문은 상호작용할 수 있는 대상 역할이며 현재 등록된 LM.Interaction.Actor.ActiveTarget을 쓰는 설계다. 플레이어의 InteractionActionTags와 대상의 HasTagContainer에 같은 등록 종류를 넣어 기존 HasAny를 통과시킨다. 문 자체를 해킹해야 한다면 그 문에 해킹 컴포넌트를 붙인다. 다른 단말이 외부 보상으로 여는 문은 그 단말의 ResultReceivers에 넣고 ApplyHackingResult에서 한 번만 연다. 자기 자신을 수신자로 넣거나 같은 열기를 단말의 본래 Interact에도 연결하지 않는다.
- 영구(현 액터 수명) 잠금은 **대상의 ULMHackingComponent.HackingStateTag 한 값**이다. LM.State.Hacking.NeedHacking 또는 LM.State.Hacking.HackedComplete의 정확한 값만 허용한다. 미지원 값은 거절/로그. HasTagContainer나 플레이어 요청 태그에 이 값을 복제하지 않는다. 일반 동작의 Busy는 InteractionComponent에, 해킹 예약은 HackingComponent의 진행 상태와 정리 가드에 둔다.
- 퍼즐 원본은 FLMHexPuzzleDefinition(Rows/Cols), 셀은 FLMHackingCell, 전체 값/횟수/Phase는 ULMHackingComponent. BuildCells/SubmitMove/RetryPuzzle은 재사용한다. 값 0–15(표시 0–F), 행 우선, 같은 값 상하좌우만 치환, 한번에 1회 소비/알림, 마지막 수 성공 우선. 잘못된 값·인덱스·같은 숫자는 무소비; 이미 풀렸거나 잘못된 정의는 시작 실패. 셀 포인터는 외부에 내놓거나 연결 이후 재할당하지 않는다.
- 해킹 컴포넌트가 원래 Pawn·Controller·ASC·Interaction(약참조), 현재 위젯(UPROPERTY), 제한 1카운트·일시정지/화면 전환을 관리한다. 컨트롤러 BP에는 위젯 클래스 기본값만 둔다. PC에 활성 단말/위젯 등록 없음. UI의 네 요청 SubmitMove/RetryPuzzle/CancelHacking/ConfirmHacking에는 발신 ULMHackingWidget* SourceWidget을 추가한다. 해당 위젯이 자기 자신을 넘기고 컴포넌트가 현재 위젯과 비교한다. 위젯 안의 셀은 부모에게 인덱스와 값만 전달한다. 기존 BP 노드 사용처가 있다면 새 핀을 연결한다. C++ 호출부는 현재 선언·정의 외 발견되지 않았다. 기존 BP 조회·이벤트는 유지한다. 얇은 ULMHackingWidget + WBP_LM_HackingPuzzle을 제안: 자기 컴포넌트로만 초기화/해제, 모델 계산 없음. 데코·VFX는 BP.
- 잠금 행 WBP_LM_InteractionEntry는 TargetActor의 해킹 컴포넌트를 구해 처음에 아이콘/Lock을 그린다. 없거나 완료면 숨긴다. 소유한 바인딩만 해제. HackingStateTag 전용 변경 알림을 완료 확정 후 한 번 보내 현재 행만 갱신한다. 목록 필터/선택·일반 태그는 바꾸지 않는다.
- 해킹 중이라는 일시 상태는 원래 요청자(PlayerState 소유 ASC)의 별도 네이티브 태그 1카운트로 표시한다. 이름 제안 LM.State.Hacking.Active. 타 단말 세션 감지와 공통 행동 API의 입력값이며 잠금 태그나 영구 진행 해금 기록이 아니다. 이 작업에서 각 이동/능력/상호작용 코드에 해킹 전용 if를 추가하지 않는다. 행동 허용·금지 API와 실행 지점(직접 호출 포함), 퀘스트·전력·AND/OR 및 저장/전선은 별도 공통 해금 카드의 범위다. API 없이는 전 행동 차단을 통과로 판정하지 않는다.

## 시작·종료 계약
1. TryStartHacking(AActor* InInteractor)는 현재 접촉·호환되는 대상/요청 경로의 Idle + NeedHacking만 수락. 같은 월드 로컬 PC와 현재 보유 Pawn, ASC Avatar 일치, 지상·생존·정상 조작, Busy 아님, 월드 미정지, Active 불보유, 유효한 보드·위젯 클래스·보상 배열을 먼저 검사한다. 사망·기절·공중·공격(준비/회복 포함)·회피/외부 이동·기존 입력/이동 금지면 거절. 거절을 위해 공격/회피를 강제 취소하지 않는다. 회피 전용 producer는 현재 브랜치 미확인; 실제 이동 제어/회피 상태로 노출되는 범위와 후속 회피 담당의 계약을 구분한다.
2. 기존 일반 Busy와 해킹 예약은 독립이다. BP의 SetIsBusy는 기존 일반 행동의 bool만 변경한다. 해킹은 이 값을 쓰거나 풀지 않는다(bOwnsBusy 불필요). ULMHackingComponent::IsInteractionReserved()는 Starting/Playing/Failed/AwaitingConfirmation 및 시작·정리·완료 전달 중이면 참. InteractionComponent의 GetIsBusy()와 EvaluateInteraction의 기존 Busy 검사는 '기존 bool 또는 이 예약'을 사용한다. 먼저 기존 조건을 검사한 뒤 Starting을 세운다. 이로써 해금 태그가 이미 Completed여도 확인/보상 콜백 안에서 본래 Interact로 우회하지 못한다. 일반 BP가 스스로 건 Busy는 보존된다.
3. 동기 진입(게임 스레드, latent 없음). GameOnly 정상 기준은 원래 로컬 PC/게임 viewport·현재 Pawn·ASC Avatar, 미정지, 커서 숨김, viewport.IgnoreInput()==false 및 영구 마우스 캡처, 게임 viewport 포커스, 이동·시선 입력 사용 가능이다. 포커스 있는 다른 모달에서는 거절한다. 지금 브랜치에 범용 입력 모드 getter/모달 관리자는 없다(디버그 문자열에 의존하지 않는다). 아래 동작을 원래 세션 기준으로만 수행한다.
   - 사전검사 → Starting·참조·시작 호출 가드 → 첫 외부 콜백 전에 Pawn 교체·Pawn/PC 종료·자기 위젯 외부 제거 구독. 태그 소유 표시 후 원래 ASC에 Active +1. 다른 단말도 첫 콜백부터 차단. 콜백이 취소를 요구하면 시작 취소를 예약하고, 진행 중인 호출이 반환할 때까지 예약·태그를 유지한다. 각 외부 호출이 반환하면 **그 호출이 실제 얻은 자원부터 기록**하고 같은 시작 호출/취소 여부·원래 관계를 다시 검사한다. 취소된 시작 호출만 자기 자원을 되돌린다. 이전 스택이 새 세션에 UI나 pause를 붙이지 않는다.
   - 실제 스캔 GA를 LM.InputTag.Scan 정확 일치 spec 핸들로만 취소하고 비활성 확인 후 StopScan으로 하이라이트·후처리 복원. 취소되지 않으면 진입 거절, 쿨다운 GE 변경/스캔 자동 재시작 없음. 보드·위젯·설정 검사는 이를 앞선다. 공격/회피는 강제 취소하지 않는다.
   - 기존 FlushPressedKeys()는 CancelAbilityInput() → 인자 없는 ClearAbilityInput() → Super로 이어진다. 해킹에서 기대 Pawn/ASC를 받는 PC의 작은 공통 키 정리 함수와 기존 override가 같은 경로를 쓰게 한다. 원래 Pawn=PC.GetPawn·ASC=PC의 ASC·ASC.Avatar=Pawn일 때만 ClearAbilityInput(ExpectedPawn); 콜백 후 세 관계를 다시 확인한 뒤에만 Super::FlushPressedKeys()를 호출한다. 평소 Pawn이 없는 컨트롤러의 엔진 동작은 유지한다. ProcessAbilityInput의 pause/blocked 중 입력 정리도 유효했던 Avatar를 넘겨 동일한 취소 루프의 새 Avatar 침범을 막는다. 캐릭터의 CancelMoveInput(필요한 C++ 접근만 열기)·CancelPendingJump도 원래 조종자가 아직 같을 때만 쓴다.
   - 각 세션마다 새 위젯. 원래 PC를 owning player로 초기화하고 컴포넌트의 현재 위젯으로 지정한 뒤 AddToPlayerScreen()과 UGameViewportSubsystem::IsWidgetAdded(현재 위젯)를 확인. 월드 정지 성공(선행 pause는 거절)과 UIOnly·커서·포커스를 확인한다. 구독 후 Playing 스냅샷을 한 번 읽는다. 화면 등록/정지 실패·위젯 외부 제거·조종 교체 시 일부 성공분까지 같은 취소로 정리. IsCurrentSessionValid()는 시작 전 조건을 재사용하지 않는다. 지금도 PC↔Pawn↔원래 ASC Avatar가 일치하고, 자기 예약·Active 1카운트 소유, 같은 실제 부착 위젯, 적법한 Phase·미정리 상태인지를 본다. 입력은 발신 위젯의 동일성까지 검사한다.
   - ULMHackingWidget::RemoveFromParent()는 **자기 위젯을 AddToPlayerScreen 중일 때만** 실제 제거를 보류하고 원래 시작 호출에 취소를 알린다. UE 5.8.4는 위젯 등록→TakeWidget/Construct→실제 화면 부착 순서라 Construct에서 바로 제거하면 화면에 입력을 잡는 잔상이 남을 수 있다. Add가 반환하면 부착 결과를 기록하고 추가 중 가드를 내린 뒤 자기 위젯을 RemoveFromParent → Super로 한 번 제거한다. 그 외 제거는 원래 경로. WBP는 서브시스템 직접 제거/RemoveAll로 소유자를 우회하지 않는다.
4. Playing→Failed(횟수 소진)→RetryPuzzle→동일 초기 배열/횟수의 Playing. Playing→AwaitingConfirmation(정답)에서 보드 입력·보상 잠금, 메시지·힌트와 월드 정지를 유지. Playing/Failed 사용자 닫기/ESC는 취소→Idle. 성공 화면에서 **사용자** 닫기/ESC만 Confirm. 위젯 외부 제거/PC·Pawn·단말 종료/조종 교체는 Awaiting 포함 **강제 취소**. 취소/실패/종료에 보상 없음. 세션 소유자가 종료를 구독한다(OnPossessedPawnChanged, EndPlay, 해당 위젯 OnWidgetRemoved 등); 유효한 입력이 들어올 때까지 기다리지 않는다.
5. ReleaseSession/내부 강제 중단은 유효 입력 검사를 전제하지 않는다. cleanup/확정 전달 가드를 먼저 세우고 예전 위젯의 컴포넌트 연결·바인딩을 무효화한다. 해당 위젯만 제거하고, 소유한 pause를 원래 월드에서만 풀며 게임 입력·커서·포커스도 자신이 전환한 같은 로컬 PC/viewport에만 복원한다. 복구 목적지는 GameOnly+원래 커서(숨김)+게임 viewport. 기존 포커스가 자기 위젯/자식 또는 외부 제거로 비어 있으면 복원하고, 외부 UI가 이미 모드·포커스를 인계받았다면 덮지 않는다. Pawn 교체 시 새 Pawn에 키·능력 정리 금지. PC 소멸로 살아 있는 원래 월드가 멈춰 있으면 그 월드의 GameMode 일시정지 정리 경로를 사용한다. 종료 중인 월드에는 새 UI·포커스를 만들지 않는다. 미확정 생존 단말만 초기값/Idle·NeedHacking으로 되돌린다. 세션 자료와 소유 플래그를 비운 뒤 **마지막 플레이어/월드 조작**으로 원래 ASC에서 자신의 1카운트만 제거한다. 그 알림이 다른 단말을 열어도 이전 경로는 입력/월드/새 ASC를 건드리지 않는다. 같은 단말의 예약은 모든 동기 완료 콜백이 돌아올 때까지 유지. 중복 종료 호출은 무효.
6. Confirm은 현재 활성 위젯/세션의 AwaitingConfirmation에서만 한 번. 외부 수신자와 원본/요청자 약참조, 알림·유효성 재검사에 필요한 정보를 지역 스냅샷으로 확보 → Phase=Completed + HackedComplete를 외부 콜백보다 먼저 기록 → 정리·목록 잠금 표시 갱신 → 중복 제거한 외부 대상마다 ILMHackingResultReceiver::Execute_ApplyHackingResult(Receiver, HackedActor, Interactor) → 마지막 OnHackingCompleted(VFX/사운드). ApplyHackingResult는 BlueprintNativeEvent. 빈 목록=힌트만, 초기 null·자기 자신·타 레벨·인터페이스 누락은 시작 거절, 중복만 제거. 전달 시 소멸/무효 수신자 각각 건너뛰고, 앞 콜백이 단말/요청자를 파괴해도 남은 유효 수신자에는 nullable 원본/요청자를 보낸다. 소유자 유효할 때만 마지막 연출. 보상 재시도/완료 롤백 없음.

## 수동 개발 단위 (개발자 검증)
| 순서 | 실물/선행 조건 | 이 단위가 끝났다는 증거 |
|---|---|---|
| 1. 대상과 자물쇠 | 기존 WBP_LM_InteractionEntry와 두 실제 역할.
