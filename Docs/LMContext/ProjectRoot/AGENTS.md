# LMProject Codex 지침

이 프로젝트의 명명 규칙과 코드 작성 규칙 원본은 [Dev/AGENTS.md](Dev/AGENTS.md)이다.
코드, 애셋, 폴더를 새로 설계하거나 작성하기 전과 예시 코드를 제시하기 전에 해당 문서를 읽고 프로젝트 작업에 공통으로 적용한다.
명명 규칙과 코드 작성 규칙을 변경할 때는 원본을 수정하고, 이 파일에는 규칙을 중복 작성하지 않는다.

규칙 문서화는 기존 코드, 애셋, 폴더의 이름 변경을 지시하지 않는다.

## 코드 변경과 PR

- 앞으로 모든 코드 변경은 해당 Git 저장소에서 별도 작업 브랜치로 관리하고 커밋한다. Lumia 코드 저장소는 `Dev`이다.
- 작업 시작 시 사용자가 실제 작업 중인 브랜치를 확인하고 PR의 대상 브랜치로 삼는다. 사용자의 브랜치와 미커밋 변경을 보존하도록 별도 워크트리에서 수정한다.
- 변경을 작업 브랜치에 푸시하고 PR을 생성한 뒤, PR 링크와 변경 내용·검증 상태를 사용자에게 제시하여 검토를 요청한다.
- 사용자가 PR 반영을 명시적으로 승인하기 전에는 사용자 작업 브랜치에 직접 수정·병합·체리픽하지 않는다. 코드 구현 승인은 병합 승인으로 간주하지 않는다.

## 시각 디자인 지침

이 프로젝트의 다이어그램과 설계 문서 등 시각 자료를 만들거나 수정할 때 적용한다.

- 기본 색 조합은 어두운 자주색 계열 보라 `#26152D`, 밝은 주황 `#FFAA4C`, 스카이블루 `#8CD9F3`를 사용한다. 보라:주황:스카이블루의 전체 시각적 비중은 **4:4:2**를 기준으로 한다. 글자와 선에는 가독성을 위한 밝거나 어두운 대비 색을 사용할 수 있다.
- **내용 구성에 맞춰 디자인한다.** 4:4:2를 고정된 세로 3분할이나 동일한 박스 배치로 강제하지 않는다. 정보의 계층, 관계, 분량과 긴 클래스명에 맞춰 영역 너비, 박스 크기, 여백, 배치 방향, 캔버스 크기와 분할 방식을 조정한다. 정확한 픽셀 비율보다 내용 전달과 가독성을 우선하면서 색 조합과 전체 비중을 유지한다.
- 레이아웃에 맞추기 위해 기존 내용, 클래스명, 관계, 수치, 확정·제안·미정의 구분을 임의로 삭제하거나 바꾸지 않는다. 공간이 부족하면 먼저 배치와 영역 크기를 조정하며, 글자를 과도하게 줄이거나 식별자를 부자연스럽게 끊지 않는다.
- 같은 문서 묶음은 글꼴, 제목과 본문의 위계, 박스·선·화살표·범례 표현을 일관되게 유지한다. 내용에 필요한 배치 차이는 허용하며, 색이나 위치가 관계의 의미를 왜곡하지 않게 한다.
- 완성본은 실제로 렌더링해 글자 잘림, 겹침, 연결선 충돌과 색 대비를 확인한다. 이후 사용자가 지정한 디자인 요구는 이 기본 지침보다 우선한다.

## Codex 컨텍스트 보존

공유 가능한 구성은 기존 `Dev` Git 저장소에서 관리한다. `Dev/.agents/skills/planning-with-files/`, `Dev/.codex/hooks.json`, `Dev/Docs/LMContext/README.ko.md`는 Git 관리 대상이며 P4에서 제외한다. 복잡한 작업 전에 해당 안내와 `Dev/AGENTS.md`를 읽는다. 작업 기록은 개인 로컬 `Dev/.planning/<ID>/`의 세 파일에 유지하고 새 세션·압축 후 다시 읽는다. 팀이 알아야 할 내용만 `Dev/Docs/LMContext/Team/`에 검토하여 요약한다. 모든 Markdown은 P4에서 제외하고, 공유/개인 분류는 `Dev/Docs/LMContext/SHARING.ko.md`를 따른다. 현재 PC의 상위 폴더 훅은 Dev로 연결하며, 팀원은 `Lumia.uproject`가 있는 개발 프로젝트 폴더에서 시작한다.
